# Chapter 36: iPhone — 三位一体

## Core Idea
iPhone 的起点不是“做手机”，而是“防止 iPod 被手机吃掉”。乔布斯先尝试与摩托罗拉合作，失败后决定自己控制硬件、软件与交互。多点触控、全屏、无键盘、应用生态，重新定义了手机。核心战略是自我颠覆：与其被别人吃掉，不如自己吃掉自己。

## Frameworks Introduced
1. **自我颠覆（Self-Cannibalization）** — 手机可能吃掉 iPod，苹果选择自己做手机。Use when 新技术可能侵蚀现有业务：主动推出替代品，而不是保护旧产品。
2. **端到端控制（End-to-End Control）** — 硬件、软件、交互、运营商关系全部自己掌控，拒绝委员会式产品。Use when 体验被多方拼凑破坏：收回关键环节。
3. **交互范式跃迁（Interaction Paradigm Shift）** — 用多点触控 + 全屏替代键盘/滚轮，重新定义“手机能做什么”。Use when 现有交互成为瓶颈：从人的动作出发，而不是从硬件出发。
4. **保密项目制（Secrecy & Small Teams）** — iPhone 项目高度保密，团队隔离。Use when 产品易被模仿：控制信息，集中资源。

## Key Concepts
- **iPod 威胁**：手机内置音乐播放器可能取代 iPod。
- **Motorola ROKR**：合作失败，体验糟糕。
- **多点触控**：iPhone 的核心交互。
- **“三位一体”**：iPod、手机、互联网通讯器合一。
- **2007 年 1 月发布**：iPhone 重新定义智能手机。
- **App Store**：后来成为生态核心。

## Mental Models
- **Use 自我颠覆 when 新技术威胁主业**：问“如果别人做，我会失去什么”，然后自己做。
- **Use 端到端 when 体验被拼凑**：硬件、软件、内容、渠道必须统一决策。
- **Use 交互跃迁 when 现有输入方式限制场景**：从用户动作出发重新设计。
- **Use 保密 when 先发优势关键**：小团队、隔离、控制信息。

## Anti-patterns
- 保护现有产品，拒绝可能侵蚀它的新技术。
- 与多方合作拼凑产品，导致体验割裂（ROKR 教训）。
- 在旧交互上修修补补，而不是重新定义问题。

## Worked Example
iPod 占苹果收入 45%，但乔布斯判断手机可能取代它。他先与摩托罗拉合作 ROKR，结果产品丑陋、难用、只能存近百首歌。乔布斯愤怒：“我受够了跟摩托罗拉这些愚蠢的公司打交道。我们自己来。”苹果收购/自研多点触控，做出一款“iPod + 手机 + 互联网通讯器”的设备。2007 年 iPhone 发布。这个案例说明：最好的防守是自我进攻。

## Key Takeaways
1. 自我颠覆比被动防守更安全。
2. 端到端控制能创造完整体验，但要求组织能力。
3. 交互创新往往来自“重新定义问题”。
4. 与多方拼凑产品，容易产生委员会式平庸。
5. 保密与小团队能加速突破。
